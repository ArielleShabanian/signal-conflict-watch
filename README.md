# SIGNAL · Conflict Watch — public website edition

A mobile-friendly, source-linked Iran–Israel–US regional conflict tracker.

**State:** The project is ready to deploy, but opening the HTML file does **not** activate the scheduled update system. You must publish the repository with GitHub Pages and run GitHub Actions once for its first data refresh.

## What changes automatically?

- The GitHub Action checks public news search RSS feeds approximately every six hours, including military, civilian, diplomatic, and explicit prophecy-related coverage.
- The website downloads the generated `data/feed.json` and rechecks every 10 minutes while open.
- Headlines are publisher-attributed and link to the report through Google News. Automated headlines are **not independently verified** and never receive a "confirmed" status automatically.
- The provisional 1–10 *headline indicator* is computed from conservative keyword/volume rules. It is **not a human judgment, official DEFCON, the probability of nuclear war, or a measure of danger to US residents**. A 9 or 10 will never be assigned by the automatic rules; those categories require human review.
- An older human-curated October 29, 2026 snapshot appears before the first successful refresh.
- The site does **not** sync with your ChatGPT scheduled alerts, and it cannot send push notifications or emergency alerts on its own.

## Publish it publicly with GitHub Pages

GitHub Pages is available for public repositories on free GitHub accounts. GitHub Actions can build and publish this self-contained website, subject to GitHub account quotas and scheduler delays.

1. Get a free [GitHub account](https://github.com/signup) if you do not already have one.
2. Create an **empty public repository** named `signal-conflict-watch` at <https://github.com/new>. Do not add an autogenerated README since this folder already has one.
3. Unzip `signal-conflict-watch-live.zip` and upload **the files inside the `signal-live` folder**, preserving subfolders including `.github/workflows`, `scripts`, and `data`. GitHub Desktop or Git can upload a full folder reliably.
4. In the GitHub repository, open **Settings → Pages → Build and deployment → Source: GitHub Actions**.
5. Open **Actions → Refresh news and publish SIGNAL → Run workflow** (or push to `main`). The workflow fetches the news, saves `data/feed.json`, and deploys the site.
6. After the Actions job finishes successfully, open the URL shown under **Settings → Pages**. Typically it is `https://YOUR_USERNAME.github.io/signal-conflict-watch/`.

### If you prefer the command line

Inside the extracted `signal-live` folder, after creating your empty repository:

```bash
git init
git branch -M main
git add .
git commit -m "Launch SIGNAL live dashboard"
git remote add origin https://github.com/YOUR_USERNAME/signal-conflict-watch.git
git push -u origin main
```

Replace `YOUR_USERNAME` with your GitHub username, then enable GitHub Pages as in step 4. If your repository is not empty, follow GitHub's instructions before pushing.

## Run locally

Use Python 3.10+ to serve the site and test the feed. No third-party packages or API keys are required.

```bash
python -m http.server 8000
# Then open http://localhost:8000 in your browser.
```

To refresh news manually (requires internet access):

```bash
python scripts/update_feed.py
```

**If a feed is unavailable**, the script preserves previous successful data and the site labels stale news scans as delayed. Google News RSS is an unofficial search feed and can change or become unavailable. The GitHub Actions run log reports any feed failures.

## Personal notes and privacy

The **Add update** and **Add rating** buttons save to your own browser's local storage only. Those notes do **not** publish to the public site, and exporting saves only your local notes. If you want to make an editorial item visible to the whole world, its content must be added to the website's underlying repository and republished.

Only publish information you are comfortable making public. The repository and website will be publicly accessible. Do not add login credentials or private personal information.

## Technical transparency

- `index.html` — accessible responsive dashboard and browser-side renderer
- `data/feed.json` — published RSS snapshot and provisional score history
- `scripts/update_feed.py` — source filter, parsing, duplicate detection, and conservative headline indicator
- `.github/workflows/publish.yml` — six-hour refresh and public GitHub Pages deployment
- `manifest.webmanifest` and `favicon.svg` — home-screen appearance

No backend database, tracking pixels, advertising, paid API, or hidden AI-generated assertions.

## Limitations

This project provides situational context, not a fact-checking service. Automated matching can miss important news, include irrelevant headlines, repeat similar articles, and overlook the difference between an allegation and a confirmed event. Verify consequential claims with primary statements and independent reporting; use official safety services for emergencies.
